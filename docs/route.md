# 지도 작성 후 경로 이동

엔트리: `code_moving_robot/route/route_run.py`  
스택: `docs/moving_stack.md`

로봇을 **직접 천천히 몰면서** 지도를 쌓는다. 테스트 주행은 **1초마다** 경로 점이 찍힌다. 도착에서 `k`로 기록을 끄고, 시작으로 돌아와 `r`이면 그 경로를 재생한다. 저장 경로가 있으면 시작 때 재생/기록을 고른다. 시연은 저장 JSON을 그대로 쓴다. ROS/Nav2 없음.

지도는 홀만 믿지 않는다. 스캔을 기존 벽에 맞춘 뒤에만 칸을 그린다 (스캔-투-맵 SLAM). 맞추지 못한 스캔은 버려서 벽이 원형으로 돌지 않게 한다.

이전 실행에서 저장한 맵이 있으면, **같은 시작 칸**에 두기만 하면 앞이 반대여도 스캔으로 yaw를 맞춘 뒤 저장한 도착으로 `r` 할 수 있다. `r`을 누를 때마다 스캔으로 지금 경로 번호를 다시 맞춘 다음, 그 점부터 따라간다. 재생 중에는 지도를 다시 그리지 않고, 종료 때도 PGM을 덮지 않는다. 맞춤이 실패해도 빈 지도로 갈아타지 않는다.

홀만으로 번진 옛 PGM은 지우고 다시 그린다.

```bash
rm -f maps/last_map.pgm maps/last_route.json
```

## 한 번만

```bash
cd code_moving_robot
uv pip install --python .venv/bin/python gpiozero
```

`robot/pins.py`의 `TRACK_M`을 좌우 바퀴 **접지 중심 사이** mm를 자로 재서 미터로 넣는다. 이 값이 틀리면 회전할 때 지도와 로봇 위치가 어긋난다.

라이다는 수평에 가깝게. 기울여 만든 지도는 윤곽용이고 경로용 최종 맵으로 쓰지 않는다.

## 실행

로봇을 **시작하려는 칸**에 둔다. 첫 실행(저장 맵 없음)이면 앞이 맵의 +x(처음 전진 방향)이게 맞춘다. 켠 위치가 (0,0), 그때 앞이 yaw 0이다.

저장 맵이 있으면 같은 칸에만 두면 된다. 앞 방향은 반대여도 된다. 시작 직후 라이다가 지도를 보고 yaw를 맞춘다.

```bash
cd code_moving_robot
.venv/bin/python route/route_run.py
```

글이 나온 뒤, 저장 경로가 있으면 `1` 재생(기본) / `2` 기록을 고른다. Enter, **그다음** 모터 6V를 켠다. SSH면 터미널이 포커스를 가진 채 키를 누른다. Enter를 칠 필요 없다.

## 키

| 키 | 동작 |
|---|---|
| `w` `s` | 전진 / 후진. 누르고 나면 유지, 멈출 때 스페이스 |
| `a` `d` | 제자리 좌/우회전 |
| 스페이스 | 바퀴 정지 |
| `↑` `↓` | 속도 업/다운. 가는 중에도 바로 반영. 재생 중에도 됨 |
| `k` | 경로 기록 on/off. `w` `e` 옆이 아니라 일부러 떨어뜨림. 도착 칸에서 끄면 지금 자리가 `G` |
| `1` | 지금 위치를 시작점으로 다시 기록 |
| `2` | 지금 위치를 경유점으로 수동 추가 |
| `3` | 지금 위치를 도착으로 하고 기록 종료 |
| `m` | ASCII 지도 + 파일 저장. `S` 시작, `G` 도착, `R` 로봇 |
| `p` | 숫자 좌표 |
| `l` | 지금 스캔으로 경로 위 위치를 다시 찾음. 중간에 두거나 제자리 회전 뒤 |
| `S` | 지도 저장 (`s`는 후진) |
| `r` | 저장·기록한 경로 재생. 누를 때마다 스캔으로 지금 점을 맞춘 뒤, 그 번호부터 따라감. `G` 근처면 시작으로 |
| `t` 또는 아무 키 | 자율 중이면 수동으로 멈춤 |
| `q` | 종료. 라이다 DTR 정지, 지도 저장 |

시작점은 프로그램을 켠 자리가 기본이다. 보통 `1`은 안 눌러도 된다. 제자리에 서 있으면 점이 안 늘어난다. 간격은 `RECORD_DT`(1초), `RECORD_MIN_M`(0.25m).

## 권장 순서

1. 시작 칸에 두고 실행한다. 저장 경로가 있으면 `1` 재생(기본) / `2` 기록.
2. 새 테스트면 `w`로 **시연할 길 그대로** 천천히 간다. `경로 n ...`이 찍힌다.
3. 도착 칸에서 `k` (또는 `3`). 기록이 끝나고 그 자리가 `G`.
4. 시작으로 **직접** 돌아온다. 이때는 점이 더 안 붙는다.
5. `m`으로 벽과 `S`/`G`를 본다.
6. `r`. 찍혀 있는 점을 따라 `G`로 간다.
7. `q`로 끝낸다. 다음 시연은 시작 칸에 두고 다시 `r`.

`r`은 찍어 둔 점(빵가루)을 순서대로 따라간다. 맵의 `#` 조각이 길을 막았다고 전체를 버리지 않는다.

자동 중 전방 장애물, 라이다 스캔이 `LIDAR_STALL_S`(1.2초) 끊김(바닥에 걸린 경우), 또는 경로 남은 거리가 `STALL_S`(3초) 동안 거의 안 줄면 **약 50cm 후진 → 좌우 여유 확인 → 좁게 옆 이동 → 맞은 앞 약 45cm만 가상 장애물로 남기고 A*로 재연결**한다. 제자리 회전·SLAM 흔들림은 움직임으로 보지 않는다. 좌우가 둘 다 막히거나 후진이 안 되면 수동. 한 웨이포인트에서 연속 `RECOVER_MAX`(4)회를 넘기면 수동. 다음 점을 통과하면 횟수는 다시 0부터.

자동 중에는 자홍색으로 `점 i/n`(지금 번호/전체 기록 점), 지금 좌표, 다음 점, 남은 거리, 앞각을 찍는다. 중간에서 출발해도 남은 개수가 아니라 원래 번호다. 회복 중에는 노란 `[회복 ...]`. SSH TTY면 색, 파이프면 무색.

## 저장 파일

- `maps/last_map.bmp` — 윈도우에서 열리는 그림. scp는 이걸 쓴다
- `maps/last_map.pgm` — 격자
- `maps/last_map.txt` — `m`과 같은 ASCII
- `maps/last_route.json` — 시작·경유·도착·마지막 포즈

`m`을 누르면 바로 저장한다. `q`를 안 눌러도 된다. 터미널에 나온 **절대 경로**를 scp에 그대로 넣는다.

```bash
scp USER@파이IP:/여기/나온/절대경로/last_map.bmp .
```

문서의 `code_moving_robot/maps/...` 상대 경로는 홈이 아니면 실패한다. PGM은 윈도우 사진 앱이 못 연다. BMP를 연다.

## 한계

- 홀은 미끄러짐을 모른다. SLAM이 벽을 보고 yaw를 고친다. 빈 복도에서는 홀만 남는다.
- 후진·회전 부호는 **마지막 모터 명령**을 따른다. 손으로 밀면 좌표가 틀린다. 그때는 `l`.
- 라이다 기울기·흔들림은 벽을 늘리거나 바닥에 찍는다.
- 재실행 방향 맞춤은 **시작 칸(또는 종료 때 자리)** 근처에서만 된다. 다른 칸에 두면 빈 지도로 다시 그린다.
- 좌우가 뒤집힌 맵이면 `robot/pins.py`의 `LIDAR_ANGLE_SIGN`을 `+1`로 바꾼다.
- 바닥 장애물은 스캔 높이에 없어서 맵에 안 남는다. 라이다가 걸리거나 정체되면 후진·우회한다. 양쪽이 좁으면 수동.
