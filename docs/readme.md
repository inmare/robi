# 부품 대기 중 할 일 (약 1주일)

방금 시작했던 코드 수정은 모두 원상복구했습니다. 앞으로는 코드 파일을 직접 수정하지 않고, 작성 순서와 각 부분의 역할만 설명하겠습니다.

## 현재 적재함 코드 구성

- `main.cpp`: 모터 동작 순서 담당
- `sensor.h`: 거리센서 공통 함수 선언
- `sensor_hw.cpp`: 실제 VL53L0X 처리
- `sensor_wokwi.cpp`: Wokwi에서 초음파센서로 거리 입력 대체
- `platformio.ini`: 실제 보드와 Wokwi 빌드 분리

현재 `main.cpp`는 다음까지만 구현돼 있습니다.

1. 리프트 모터 상승
2. 거리센서가 100mm 이하인지 확인
3. 리프트 정지
4. 푸셔를 150스텝 전진
5. 푸셔 정지

아직 없는 기능은 푸셔 복귀, 리프트 하강, 리미트 스위치, 원점 복귀, 시간 초과, 비상 정지, 중앙 통신입니다.

## 1단계: 핀 배치부터 정리

가장 먼저 코드 상단에 핀을 기능별로 정리하고, 각 핀 옆에 주석을 작성하세요.

일반 CNC Shield V3 기준:

- 리프트 X축: STEP D2 / DIR D5
- 푸셔 Y축: STEP D3 / DIR D6
- 드라이버 공통 Enable: D8
- 리미트 스위치 4개: A0~A3 검토
- VL53L0X: A4 SDA / A5 SCL

현재 코드는 `DIR D2 / STEP D3`, `DIR D4 / STEP D5`라 CNC 쉴드 표준과 맞지 않습니다. Wokwi에서는 A4988을 직접 연결했기 때문에 동작할 수 있지만, 실제 쉴드에 올리기 전에는 반드시 SZH-ET004 기판 표기를 확인해야 합니다.

주석에는 핀 번호뿐 아니라 다음도 적으세요.

- 어느 모터인지
- HIGH일 때 어느 방향인지
- 스위치가 눌리면 LOW인지 HIGH인지
- 단위가 mm, ms, step 중 무엇인지

## 2단계: 모터 한 개씩 함수로 분리

처음부터 전체 자동 동작을 만들지 말고 다음 기능을 각각 독립적으로 작성합니다.

- 리프트 상승
- 리프트 하강
- 리프트 정지
- 푸셔 전진
- 푸셔 후진
- 푸셔 정지
- 전체 드라이버 활성화/비활성화

이 단계에서는 시리얼 문자로 시험하면 됩니다.

- `u`: 리프트 상승
- `d`: 리프트 하강
- `p`: 푸셔 전진
- `r`: 푸셔 후진
- `s`: 전체 정지

주석에는 “이 함수가 핀을 어떻게 바꾸는지”보다 “왜 이 방향으로 움직이는지”를 적는 것이 좋습니다.

## 3단계: 센서와 스위치만 따로 확인

모터를 빼고 입력만 확인합니다.

- VL53L0X 거리 출력
- 리프트 하단 스위치
- 리프트 상단 스위치
- 푸셔 후진 원점 스위치
- 푸셔 전진 끝 스위치

시리얼 모니터에 각각 `0/1`을 출력해서 손으로 눌렀을 때 정확히 바뀌는지 확인하세요.

현재 코드는 `sensorHasError()`를 거리 읽기 전에 확인합니다. 실제 코드에서는 거리를 읽은 뒤 해당 읽기가 타임아웃인지 검사하는 흐름이 더 자연스럽습니다.

## 4단계: 상태 정의

여러 `bool`을 계속 추가하기보다 시스템이 현재 어느 단계인지 하나의 상태로 관리합니다.

필요한 상태:

1. `WAITING`: 시작 대기
2. `HOMING_PUSHER`: 푸셔 원점 복귀
3. `HOMING_LIFT`: 리프트 하단 복귀
4. `LIFTING`: 책 높이까지 상승
5. `PUSHING`: 책 밀기
6. `RETURNING_PUSHER`: 푸셔 복귀
7. `LOWERING`: 리프트 하강
8. `COMPLETE`: 작업 완료
9. `FAULT`: 오류 정지

각 상태 위에 다음 형식으로 주석을 작성하면 이해하기 쉽습니다.

- 진입 조건
- 현재 움직이는 모터
- 완료 조건
- 실패 조건
- 다음 상태

## 5단계: 상태 전환 작성

전체 순서는 다음과 같습니다.

`대기 → 푸셔 원점 → 리프트 원점 → 상승 → 푸시 → 푸셔 복귀 → 리프트 하강 → 완료`

예를 들어 `LIFTING`에서는:

- 리프트 상승 펄스를 발생
- 일정 간격으로 VL53L0X 측정
- 목표 거리 도달 시 `PUSHING`
- 상단 리미트가 먼저 눌리면 `FAULT`
- 제한 시간을 넘으면 `FAULT`

이런 식으로 각 상태가 자기 조건만 판단하게 만드세요.

## 6단계: 안전 기능 추가

자동 동작이 된 다음 추가합니다.

- 각 동작의 최대 실행 시간
- 모터 정지 함수 하나로 통일
- 거리센서 오류 시 정지
- 리미트 스위치 모순 시 정지
- 시리얼 비상 정지 명령
- 오류 발생 시 Enable D8로 드라이버 비활성화
- 오류 후 자동 재시작 금지

`delay()`로 수초 동안 기다리면 그동안 비상 정지를 읽을 수 없습니다. 최종 코드는 `millis()`로 경과 시간을 확인하는 방식이 좋습니다. 처음 배우는 단계에서는 기존 펄스 코드를 유지한 뒤, 상태머신이 이해된 다음 비차단 방식으로 바꾸면 됩니다.

## 7단계: Wokwi 검증

실제 부품이 오기 전에는 다음 순서만 검증하면 됩니다.

1. 시작 명령 입력
2. 푸셔 원점 입력 가정
3. 리프트 하단 입력 가정
4. 거리를 100mm 이하로 변경
5. 푸셔 전진 끝 입력
6. 푸셔 원점 입력
7. 리프트 하단 입력
8. 완료 상태 확인
9. 중간에 센서 오류나 시간 초과를 넣어 `FAULT` 확인

실제 리미트 스위치가 오기 전에는 시리얼 문자나 Wokwi 버튼으로 입력을 대신할 수 있습니다.

## 이동로봇 코드는 그다음

이동로봇은 다음 순서로 별도로 작성하는 것이 좋습니다.

1. 좌우 모터 전진·후진·정지
2. 차동구동으로 직진·회전
3. 홀 센서 카운트
4. 라이다 데이터 읽기
5. 장애물 발견 시 정지
6. 적재함 탐색
7. 저속 접근
8. 좌우 리미트 스위치로 정렬
9. 주차 완료 메시지 전송
10. 출발 허가까지 대기

라즈베리 파이 코드는 라이다, 모터, 홀 센서, 중앙 통신을 각각 별도 파일로 분리하고, 메인 파일에는 상태 전환만 두는 게 이해하기 쉽습니다.
